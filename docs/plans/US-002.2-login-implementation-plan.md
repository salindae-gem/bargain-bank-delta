## Constraints

### Technical Constraints

- Login form must only require email and password (keep it simple, no complexity)
- Session must remain active for 7 days (configurable)
- Invalid credentials must show generic error message (security best practice)
- No email enumeration in responses (attackers can't identify registered emails)
- Session tokens must be httpOnly cookies or securely stored
- API response time must be < 1 second for login
- Must handle network failures gracefully

### Design Constraints

- Mobile-optimized form (quick to use on small screens)
- Consistent with Bargain Bank design system (shadcn/ui, TailwindCSS)
- No financial jargon in UI labels
- Must follow accessibility standards (WCAG 2.1 AA)
- Auto-focus email field (mobile quality-of-life feature)

### Security Constraints

- HTTPS enforced in production
- Passwords never logged or displayed in error messages
- Rate limiting on login endpoint (prevent brute force)
- Generic error messages only (don't reveal if email exists)
- Password verification using bcrypt comparison
- CSRF protection enabled
- Session tokens must be cryptographically secure
