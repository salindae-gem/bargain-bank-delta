## Technical Details

### Backend: Validation Rules

```typescript
// Zod schema
const SignUpSchema = z.object({
  email: z.string().email("Invalid email format"),
  password: z.string()
    .min(8, "Password must be at least 8 characters")
    .regex(/\d/, "Password must contain at least one number")
    .regex(/[!@#$%^&*]/, "Password must contain at least one special character (!@#$%^&*)"),
  passwordConfirmation: z.string()
}).refine(
  (data) => data.password === data.passwordConfirmation,
  { message: "Passwords do not match", path: ["passwordConfirmation"] }
);
```

### Backend: HTTP Endpoints

**POST /auth/signup**

**Request:**
```json
{
  "email": "user@example.com",
  "password": "SecurePass123!",
  "passwordConfirmation": "SecurePass123!"
}
```

**Success Response (201 Created):**
```json
{
  "success": true,
  "user": {
    "id": "uuid-here",
    "email": "user@example.com"
  },
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "message": "Account created successfully!"
}
```

**Error Response - Duplicate Email (409):**
```json
{
  "success": false,
  "error": "Email already registered",
  "field": "email"
}
```

**Error Response - Validation (400):**
```json
{
  "success": false,
  "errors": {
    "password": "Password must contain at least one number",
    "passwordConfirmation": "Passwords do not match"
  }
}
```

**Error Response - Rate Limited (429):**
```json
{
  "success": false,
  "error": "Too many signup attempts. Try again in 15 minutes"
}
```

### Frontend: Component Structure

```
src/features/Auth/SignUpPage.tsx
├── State: form values, loading, errors (TanStack Query + Zod)
├── signup mutation (TanStack Query)
├── Form elements
│   ├── Email input (validated with real-time feedback)
│   ├── Password input (with show/hide toggle)
│   ├── Password confirmation (with match indicator)
│   ├── Submit button (disabled if invalid or loading)
│   └── Error messages (field-specific or generic)
├── Success message (conditional)
└── Login link ("Already have an account?")
```

### Frontend: Form Validation Flow

1. User types → client validates with Zod in real-time
2. Show validation error below field if invalid
3. Disable submit button if any field invalid
4. On submit: if client validation passes → call API
5. On API response:
   - Success → show confirmation message → redirect after 2s
   - Duplicate email → show error below email field
   - Validation error → show specific field errors
   - Network error → show retry message

## Constraints

- **Security:** Password hashed with bcryptjs (min 12 rounds); no plaintext passwords logged
- **Security:** No sensitive error details exposed in responses; distinguish public errors (email taken) from system errors
- **Security:** Email validation prevents malformed addresses; rate limit prevents brute force attacks
- **Security:** HTTPS enforced in production
- **Performance:** Signup response < 500ms on 3G (excluding network latency)
- **Performance:** Client-side validation instant (no server round-trip)
- **Accessibility:** WCAG 2.1 AA compliance required (keyboard navigation, screen reader support, color contrast 4.5:1)
- **Mobile:** Works on iOS Safari and Android Chrome
- **Mobile:** No financial jargon in labels or instructions
- **Mobile:** Inputs must be touch-friendly (>44px height, good spacing)
- **No 2FA in MVP** (Phase 2+)
- **No email confirmation in MVP** (Phase 2+)
